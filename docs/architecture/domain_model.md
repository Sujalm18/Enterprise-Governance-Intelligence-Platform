# Domain Model — Enterprise Governance Intelligence Platform

This document describes the core domain model entities, their attributes, and relationships within the Enterprise Governance Intelligence Platform.

---

## 1. Domain Entities

### Organization (Tenant)
- **Purpose**: Defines the logical tenant boundary. All data objects are scoped to an Organization.
- **Attributes**:
  - `id`: Unique identifier (Integer)
  - `name`: Organization name (String)
  - `created_at`: Creation date-time (DateTime)

### Document
- **Purpose**: Represents an uploaded compliance file (PDF, DOCX, TXT, XLSX).
- **Attributes**:
  - `id`: Unique identifier (Integer)
  - `filename`: Full file path on disk (String)
  - `type`: File type format extension (String)
  - `upload_timestamp`: Upload date-time (DateTime)
  - `status`: workflow parsing status (Enum)
  - `tenant_id`: Scoped Organization ID (Integer)

### GovernanceReport
- **Purpose**: Structured compliance audit report generated by parsing and analyzing a Document.
- **Attributes**:
  - `id`: Unique identifier (Integer)
  - `document_id`: Associated Document ID (Integer)
  - `summary`: Short extraction summary (String)
  - `executive_summary`: Long executive boardroom summary (String)
  - `confidence_score`: AI confidence score (Float)
  - `review_status`: Workflow review state (String)
  - `reviewer`: Active reviewer user name (String)
  - `review_notes`: Justification notes for review decisions (String)
  - `processing_time_seconds`: Total extraction pipeline time (Float)
  - `tokens_used`: LLM token volume consumed (Integer)
  - `tenant_id`: Scoped Organization ID (Integer)

### RaidItem
- **Purpose**: A specific risk, action, issue, or dependency extracted from a Governance Report.
- **Attributes**:
  - `id`: Unique identifier (Integer)
  - `report_id`: Associated GovernanceReport ID (Integer)
  - `type`: "risk" | "action" | "issue" | "dependency" (String)
  - `description`: Detailed risk text (String)
  - `severity`: "low" | "medium" | "high" | "critical" (String)
  - `risk_score`: Initial risk score (Integer)
  - `current_risk_score`: Residual risk score after mitigations (Integer)
  - `suggested_owner_role`: Playbook-recommended owner role (String)
  - `explain_why`: AI-generated justification for the risk (String)
  - `suggested_actions`: AI-generated target mitigations (String)
  - `estimated_impact`: AI-generated impact scope (String)
  - `tenant_id`: Scoped Organization ID (Integer)

### EscalationItem
- **Purpose**: A dispute escalated from an audit report.
- **Attributes**:
  - `id`: Unique identifier (Integer)
  - `report_id`: Associated GovernanceReport ID (Integer)
  - `description`: Escalation details (String)
  - `severity`: "low" | "medium" | "high" | "critical" (String)
  - `status`: "OPEN" | "ROUTED" | "RESOLVED" | "CLOSED" (String)
  - `routing_target`: Role or committee routed to (String)
  - `assigned_to`: Assignee name (String)
  - `explain_why`: Justification for escalation (String)
  - `tenant_id`: Scoped Organization ID (Integer)

### MitigationTask
- **Purpose**: An actionable compliance task created to remediate a RAID item.
- **Attributes**:
  - `id`: Unique identifier (Integer)
  - `title`: Task name (String)
  - `related_raid_item_id`: Associated RaidItem ID (Integer)
  - `owner_role`: Playbook-matched owner role (String)
  - `owner_name`: Assigned owner name (String)
  - `priority`: P1 | P2 | P3 | P4 (String)
  - `risk_score`: Initial risk score inherited (Integer)
  - `target_date`: SLA completion target date (String, YYYY-MM-DD)
  - `sla_status`: "ON_TRACK" | "AT_RISK" | "OVERDUE" (String)
  - `status`: "PLANNED" | "IN_PROGRESS" | "BLOCKED" | "COMPLETED" | "VERIFIED" (String)
  - `completion_percentage`: Task progress (Integer, 0-100)
  - `effectiveness`: Mitigation effectiveness percentage (Integer, 20-100)
  - `tenant_id`: Scoped Organization ID (Integer)

### Notification
- **Purpose**: System alert generated for workflow transitions or SLA breaches.
- **Attributes**:
  - `id`: Unique identifier (Integer)
  - `severity`: "LOW" | "MEDIUM" | "HIGH" | "CRITICAL" (String)
  - `notification_type`: e.g. "SLA_BREACH", "MITIGATION_ASSIGNED" (String)
  - `title`: Alert title (String)
  - `message`: Alert description text (String)
  - `recipient_role`: Role intended to read (String)
  - `read_status`: Unread vs read toggle (Boolean)
  - `tenant_id`: Scoped Organization ID (Integer)

### AuditLog
- **Purpose**: Chronological, immutable record of all operations.
- **Attributes**:
  - `id`: Unique identifier (Integer)
  - `event`: Event category string (String)
  - `user`: Initiating username (String)
  - `user_role`: Initiating user role (String)
  - `action`: Specific operation performed (String)
  - `details`: Details description (String)
  - `timestamp`: Date-time of action (DateTime)
  - `tenant_id`: Scoped Organization ID (Integer)

### GovernanceTrendSnapshot
- **Purpose**: Historical daily snapshots of GRC metrics.
- **Attributes**:
  - `id`: Unique identifier (Integer)
  - `timestamp`: Snapshot date-time (DateTime)
  - `health_score`: Active Health Score (Integer)
  - `maturity_score`: Active Maturity Score (Integer)
  - `risk_exposure`: Total risk score sum (Integer)
  - `mitigation_effectiveness_pct`: Average mitigation effectiveness (Float)
  - `sla_breaches`: Total overdue tasks count (Integer)
  - `open_escalations`: Total active escalations count (Integer)
  - `verified_mitigations`: Total verified tasks count (Integer)
  - `critical_risks`: Total active critical risks count (Integer)
  - `notification_volume`: Total alerts volume (Integer)
  - `tenant_id`: Scoped Organization ID (Integer)

---

## 2. Key Relationships

1. **Multi-Tenancy Scoping**:
   - `Organization` stands as the absolute root. All other entities carry a `tenant_id` ForeignKey mapping back to `Organization.id` to prevent cross-tenant queries.

2. **Document to Report**:
   - A `Document` has a **1-to-Many** relationship with `GovernanceReport` (reports are version-tracked; only the latest version has `is_latest = True`).

3. **Report to Extracted Items**:
   - A `GovernanceReport` has a **1-to-Many** relationship with `RaidItem` and `EscalationItem`. Removing a report cascade-deletes its associated RAID and escalation entries.

4. **Mitigations Lifecycle**:
   - A `RaidItem` has a **1-to-Many** relationship with `MitigationTask`. A single risk item can generate multiple mitigation tasks.
   - Completing/verifying `MitigationTask` dynamically scales the `RaidItem.current_risk_score` down, reflecting residual risk.
